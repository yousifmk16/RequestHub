# AI Usage Log

Notable moments from building with AI tools. Feeds the README sections
"Technologies and AI tools used" and "Challenges encountered".

Add an entry when the AI got something wrong, needed correcting, or a tool
(MCP/skill) caught a real problem.

| Date | Task | What the AI did / got wrong | How it was caught | Fix |
|------|------|-----------------------------|-------------------|-----|
| 2026-11-25 | Plan: database | First plan kept PostgreSQL/Neon, so a fresh clone could not run without a DB account. | Reviewing the plan against the "anyone can open it with no dependencies" goal. | Switched to SQLite locally + Turso in production (D1). |
| 2026-11-25 | Install Prisma | `npm install prisma` would have pulled `8.0.0-rc.35`: the CLI's `latest` npm tag points to a release candidate while `@prisma/client` latest is 7.10.1, a major-version mismatch. | Checked `npm view prisma dist-tags` before installing. | Pinned all Prisma packages to exact 7.10.1. |
| 2026-11-25 | Prisma libsql adapter | Docs research returned the class name `PrismaLibSQL`. The installed 7.10.1 package exports `PrismaLibSql`. | Read the package's own `.d.ts` instead of trusting the summary. | Used `PrismaLibSql`. Rule: installed types beat docs summaries. |
| 2026-11-25 | Add Vitest | Install failed: the scaffold pinned `@types/node@^20`, while Vitest 5 needs Node 22+ types. | npm ERESOLVE peer-dependency error. | Fixed the root cause (target Node 24 LTS types, `engines >=22`) instead of `--legacy-peer-deps`. |
| 2026-11-25 | E2E database | Used `prisma migrate reset --force` to reset the test DB. Prisma 7 detected an AI agent and refused without explicit user consent. | Playwright webServer failed with Prisma's AI-safety message. | Did not bypass the guard. Redesigned: a script deletes the throwaway `e2e.db` and runs `migrate deploy`, which is simpler and deterministic. |
| 2026-11-25 | Requests search | First version of `listRequests` passed the search term straight to Prisma `contains`. On SQLite that is `LIKE '%term%'` without escaping, so `%` matched every row and `90%` would also match `900`. | A service integration test written for the edge case ("treats LIKE wildcards as literal") failed against a real SQLite file. | The SQL filter is narrowed with an exact case-insensitive check (D3). The regression test stays. |
| 2026-11-25 | Seed script | The shell heredoc holding the seed data broke on apostrophes in the text ("I've", "won't"), so nothing was written. | The shell reported a parse error before running anything. | Wrote the files with the editor tool instead of shell heredocs for content with quotes. |
| 2026-11-25 | Error page | The usual Next.js error boundary uses `reset()`. In Next 16.3+, `retry()` is the stable prop that re-fetches the failed segment, while `reset()` only re-renders it (so a page whose data failed to load would fail again). | Read the `error.md` bundled with the installed Next version before writing the component, as AGENTS.md requires. | Used `retry()`. |
| 2026-11-25 | Toasts | The shadcn Toaster follows `useTheme()` and falls back to "system". With no dark mode yet, a dark-mode OS would get dark toasts on a light page. | Reading the generated `sonner.tsx` before using it. | Pinned `theme="light"` until the dark-mode extra lands. |
| 2026-11-25 | E2E server | The Playwright config started a second `next dev`. Next 16 allows only one dev server per project, so E2E failed while the preview server was running. | Playwright webServer error: "Another next dev server is already running". | E2E builds and starts a production server in its own `.next-e2e` folder: no clash, and closer to production. |
| 2026-11-25 | Lakeora palette | New `bg-brand-red-strong` and `after:bg-brand-red` classes rendered transparent. First guesses (stale stylesheet, then a restart) were wrong, and stopping the background task left the old `next dev` process running, so checks kept hitting it. | Computed styles in the browser showed no rule; compiling `globals.css` directly with Tailwind's node API produced the rule correctly, which narrowed it to the dev pipeline. | Stopped the orphaned process by PID and cleared `.next`. Turbopack's persistent dev cache had kept the CSS built between the component edit and the theme edit. Lesson: if a theme token "doesn't work", compile it in isolation before changing code. |
| 2026-11-25 | Header + hero | The stale-CSS problem came back: a new `text-on-navy-muted` token rendered as plain white after editing `@theme`. | Computed style check in the browser, then the isolated Tailwind compile from last time showed the class was valid. A Turbopack loader worker process was still alive between edits. | Treated it as known dev-only behaviour: added `npm run dev:clean` (clears `.next`, restarts) and documented it in CLAUDE.md for theme edits. Production builds and e2e (fresh `.next-e2e`) are unaffected. |
| 2026-11-25 | Live logo | First version wrapped JSX in `try/catch` to fall back on DB errors. That only catches the data read, not render errors, so the code implied a safety it didn't have. | ESLint `react-hooks/error-boundaries` rule. | Moved only the data read into `try/catch`. |
| 2026-11-25 | Live logo / caching | D4 assumed database reads make pages dynamic. In a production build the local SQLite query finished during prerendering, so the header counts were baked into static HTML cached for a year (`x-nextjs-prerender: 1`, `s-maxage=31536000`). The dev server showed live data, which hid the bug. | Deliberately tested a production build: PATCHed a request to COMPLETED, the API showed 15 completed, the page still said 14. | `await connection()` before every page-level DB read (per the bundled Next docs for SQLite), placed outside `try/catch`. Re-tested: pages build as `◐`, the logo goes 14 → 15 → 14 live, responses are `no-store`. D4 corrected. |
| 2026-11-25 | Requests list filters | The selects used a bare `<SelectValue />`. Radix can only show an option's label after the client mounts, so the server HTML had empty select boxes that filled in a moment later. | A browser screenshot taken just after navigation showed blank selects; the DOM had correct values after hydration, which pointed to SSR output. Confirmed with `curl` on the server HTML. | Passed the label as `SelectValue` children (filters, sort, status pill), so the label is in the first paint. Verified with `curl`. |
| 2026-11-25 | List tweaks | After branch switches during merges, the header logo rendered black: the dev server kept a stylesheet from the moment `main` briefly had the older `globals.css`. | The product owner noticed the page looked off; the browser showed the `--mark-*` variables missing while the source and a production build both had them. | Restarted with `npm run dev:clean`. CLAUDE.md now says to use it after switching branches, not only after theme edits. |
| 2026-11-25 | Status chips | The first chip version's accessible name was the raw text "In Progress7" (label and count side by side). | Reading each chip's `textContent` while testing in the browser. | Added an explicit `aria-label`, e.g. "In Progress, 7 requests". |
| 2026-11-25 | Edit page | Adding the first dynamic route (`/requests/[id]/edit`) exposed that `MainNav`/`MobileNav` called `usePathname()` outside Suspense. Confirmed fixed by counting the error in the dev-server log before and after a fresh request (4 → 4). | Desktop nav reads the pathname inside Suspense (fallback = same links without the active underline). Mobile reads it only inside the opened menu panel. Production build passes with the edit route as `◐`. |
| 2026-11-25 | Form validation copy | An empty title said "Title must be at least 3 characters", and the department error said "Choose a category" though the UI never uses that word. | Submitting the empty form in the browser and reading the messages. | Zod `abort` gives "Title is required" for blank input; the message now says "department".
